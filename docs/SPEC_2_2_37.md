# vhcctweaks 2.2.37: what it adds

This file is the contract for 2.2.37. The mod and the craftos-agent emulator both implement exactly this. Everything in [SPEC_2_2_36.md](SPEC_2_2_36.md) still holds. 2.2.37 is built against Vault Hunters 3.21.74 and reads the things that update added: Gear Score, Gear Power, Temper and Dust.

**The safety rule.** Every call into Vault Hunters is wrapped on its own. If one fails, or the server runs a Vault Hunters without the feature, the field is left out or the function returns `nil, reason`. Nothing here raises an error and nothing can stop a tick.

**The network rule.** A player counts as online only when they are on this server. A player on another server of the network is read from what this server has saved, the same as an offline player, and Vault Hunters is never asked to load them.

All the player functions take a name or a UUID string, resolved the same way as `getPlayerBalance`. They are read-only, need no auth, touch or range, and run on the main thread. They share these errors: `"unknown player"` (a name nobody has; a well-formed UUID of nobody is not unknown, it has no data), `"looking up player '<name>' - try again"` (the first call for a name the server has not seen), and `"internal error"`.

## 1. Gear Power

| Function | Does |
|---|---|
| `ccvault.getPlayerGearPower(player)` | Returns a table, or `nil, error`. |

**For a player on this server at or above the starting level** (`minLevel`, 100 in the pack):

| Field | Meaning |
|---|---|
| `online` | `true` |
| `shown` | `true` |
| `level` | The player's vault level. It can be above 100. |
| `minLevel` | The level Gear Power starts at. |
| `greedTier` | The player's greed tier. |
| `gearScore` | Gear Score, rounded, as the game shows it. |
| `gearScoreExact` | The same before rounding: the mean of the six slot scores. |
| `gearPower` | Gear Power: `round(gearScoreExact * temper)`. |
| `temper` | The Temper multiplier: `(max(might, magic) + vigor) / 2`. |
| `might`, `magic`, `vigor` | The three multipliers that feed `temper`. 1 with no Temper. |
| `slots` | `{ head=, chest=, legs=, feet=, weapon=, offhand= }`, each a slot score from 0 to 1500. |
| `slotDetails` | `{ [slot] = { status, score, item, name, hotbarSlot, hotbarWeapons } }`. See below. |
| `peakGearPower` | The highest Gear Power the player ever reached. |

- `weapon` is the **best weapon anywhere on the hotbar**, not the held item. `slotDetails.weapon.hotbarSlot` (1 to 9) says which one counts and `hotbarWeapons` how many there were to choose from.
- `status` is Vault Hunters' own word for the slot: `COUNTED`, `EMPTY`, `NO_WEAPON`, `NOT_VAULT_GEAR`, `NOT_COMBAT_GEAR`, `INERT` (wrong slot, broken or above the player's level), `GREED_TIER_LOCKED`, `NO_TIER_CONFIG`. Only `COUNTED` slots score above 0.
- `item` is the registry name and `name` the display name of the item in the slot. Both are absent for an empty slot.
- A field Vault Hunters could not give is left out. `slotDetails` is the most likely one.

**Below the starting level:** `online = true`, `shown = false`, with `level`, `minLevel`, `greedTier` and `peakGearPower`. No scores.

**For a player who is not on this server:** `{ online = false, shown = false, level =, peakGearPower = }`. Vault Hunters only saves the peak, so that is all there is. `level` is absent when the file has none.

Errors of its own: `"no vault data"` (nothing saved for the player), `"gear power not available"` (the server's Vault Hunters is older than 3.21.74, or the read failed).

## 2. Temper and Dust

| Function | Does |
|---|---|
| `ccvault.getPlayerTemper(player)` | Returns a table, or `nil, error`. |

| Field | Meaning |
|---|---|
| `online` | Whether the player is on this server. |
| `dust` | Dust in hand. |
| `might`, `magic`, `vigor`, `tool` | Each `{ level, multiplier, power }`. |
| `gearPowerMultiplier` | `(max(might.multiplier, magic.multiplier) + vigor.multiplier) / 2`. |
| `peakGearPower` | The highest Gear Power ever reached. |
| `trialsRecord` | The furthest trial room reached. |
| `bossesBeaten` | Band bosses beaten. Online only. |
| `favorsUsed` | Altar favors taken. Online only. |

- `level` is the levels bought in that category (0 to 400).
- `multiplier` is what the category multiplies Gear Power by (Vault Hunters calls it the label). `tool` has one too, but it does not count for Gear Power.
- `power` is what the category multiplies its effect by inside a vault.
- For a player who is not on this server, `dust`, the levels, `peakGearPower` and `trialsRecord` come from the saved profile, and `multiplier` and `power` are worked out from the levels with the server's Temper ladder. If the ladder cannot be read they are left out, and so is `gearPowerMultiplier`.
- A player with a saved profile but no Temper yet gets zero Dust and zero levels.

Errors of its own: `"no vault data"`, `"temper not available"`.

## 4. Gear Score on each piece

Identified gear (`itemType == "Gear"`) gets its own Gear Score in `vaultData`, worked out by Vault Hunters' scorer. It is the score the piece has in its slot for anyone who can use it: gear never goes above level 100, so the player's level and greed tier are taken as high enough.

| Field | Meaning |
|---|---|
| `gearScoreStatus` | `COUNTED`, or why it does not score: `INERT` (broken), `NO_TIER_CONFIG`, `NOT_COMBAT_GEAR`. |
| `gearScore` | 0 to 1500, rounded. About 1000 is a perfect natural OMEGA piece; a legendary line can go above. Only when `COUNTED`. |
| `gearScoreExact` | The same before rounding. Only when `COUNTED`. |
| `gearScoreLines` | `{ expected =, actual = }`: the line count of a best natural piece of this type, and this piece's. The score divides by the larger. Only when `COUNTED`. |

Each modifier under `implicits`, `prefixes` and `suffixes` of a counted piece also gets:

| Field | Meaning |
|---|---|
| `scoreRatio` | 0 to 1.5. 1 is the best natural roll at level 100. A line with no number (a heal pair, an ability) is 1. |
| `scorePoints` | The line's share of `gearScore` before the 1500 cap: `perfect * scoreRatio / max(expected, actual)`, where `perfect` is Vault Hunters' `perfectSlotScore` (1000 in the pack). |
| `naturalBest`, `naturalWorst` | The best and worst natural roll of this attribute at level 100 for this gear type. Numeric lines with a known range only. |

- Tools, jewels, charms, etchings and unidentified gear get none of this.
- A broken piece is `INERT` with no score, as in the game.
- On a Vault Hunters older than 3.21.74 the fields are absent.
- `vaultDetails.gearScore` (default true) turns the piece fields off; `vaultDetails.gearScoreLines` (default true) turns the per-modifier fields off.

## 5. Item detail fixes

- **`isLegendary` on unidentified gear.** The forced-legendary flag is now reported before identification. On identified gear, tools and jewels `isLegendary` is also true when any modifier is legendary, not only when the flag was set.
- **`greedTier`** on gear an Etching locked to a greed tier, identified or not. Absent with no lock. The nameless entry it used to leave in `attributes` is gone.
- **Heal pairs are labelled.** Heal on Kill and Heal on Block values are `{ first, second, chance, amount }`: `chance` is `first` and `amount` is `second`.
- **`durability.max`**, the same number as `durability.total`.
- **`attribute`** on every modifier: the attribute's registry id, such as `the_vault:summon_damage`. Unlike `name`, it never changes with the display text.
- **Summon Damage** needs nothing special: it is a plain number modifier, `{ name = "Summon Damage", attribute = "the_vault:summon_damage", value, min, max, tier }`.
- **Jewels:** `size`, `state`, `identified`, `isLegendary`.
- **Tools:** `capacity`, `hammerSize`, `material`, `state`, `identified`, `isLegendary`, `isSoulbound`, `craftingPotential`. Fields with nothing to say are absent.

## 6. Smaller additions

| Function | Does |
|---|---|
| `ccvault.getLimits()` | Returns the server's limits as a table. A value that cannot be read is absent. |
| `vhcc.getUsage()` | Returns `used, limit`: the bytes this computer's folder uses and its allowance. `used` is recounted from disk at most once a minute. |

`getLimits` keys: `maxTransferAmount`, `interactionStaleSeconds`, `nonceExpirySeconds`, `authIdleTimeoutMinutes`, `maxHistoryResults`, `maxAllowanceMinutes`, `maxLinksPerComputer`, `maxBatchMoves`, `batchTimeBudgetMicros`, `maxWatchesPerComputer`, `vhccMaxBytesPerComputer`, `gearScoreInDetails`, `gearScoreLinesInDetails`.

**`moveMany` moves can name the item they expect.** A move may carry `expectName = "mod:item"`. If the item in `fromSlot` has a different name, or the slot is empty, that move moves 0 and the batch goes on. A program that planned its moves from an older look at the chest no longer moves whatever a player put there since. `expectName` that is not a string raises `bad move #n (expectName expected string)`. It is given by key only, never by position. The slot range checks and a `limit` of 0 or less come first, as before.

## Player level above 100

Vault Hunters 3.21.74 removed the level cap. `ccvault.getPlayerVaultLevel` already returns the real level, above 100 included, online and from the saved profile; nothing changed there. Gear and crystals still stop at 100, so past 100 the level is a progress number: it unlocks Gear Power and Temper at 100 and nothing after.
